# 自己紹介ページの作り方（初回専用）

このツールを初めて使う人には、まず**自分の自己紹介ページ**を作ってもらう。
題材を考えなくてよく、材料が本人の中にあり、できたものがそのまま名刺代わりに使えるため、
「作って公開する」の一周を最短で体験できる。

作り終えたら、以降は通常の図解ツールとして使う（`audience.md` の3目的に戻る）。

## 通常の図解との違い（重要）

| 項目 | 通常の図解 | 自己紹介ページ |
|---|---|---|
| リサーチ | ウェブ検索2〜3回が必須 | **不要**。本人の話が一次情報 |
| 出典セクション | 全図解で必須 | **置かない**。代わりに作成日だけ小さく添える |
| 利用目的の判定 | audience.md の3択 | 不要。「自己紹介」で固定 |
| 公開前の確認 | 個人情報を含むときだけ | **必ず行う**（後述） |

## 聞くこと

**一問一答にしない。** 下の項目をまとめて1回で提示し、答えられるものだけ答えてもらう。
非エンジニアが相手なので、埋まらない項目があって当然という前提で聞く。

> あなたのことを教えてください。答えられるものだけで大丈夫です。
> 箇条書きでも、話し言葉でも構いません。
>
> 1. **お名前**（本名でもニックネームでも、呼ばれたい名前で）
> 2. **何をしている人か**（仕事・活動を一言で）
> 3. **できること・得意なこと**（3つくらい）
> 4. **これまでの経歴**（任意。ざっくりで大丈夫です）
> 5. **連絡先やSNS**（任意。載せたくなければ「なし」で）
> 6. **誰に見せたいか**（例: 名刺代わり／仕事の相談を受けたい／採用に使いたい）

答えが薄くても、それ以上は掘らない。**足りない部分は構成でカバーする**（項目を減らす、1つの章を厚くする）。
「もっと書くことはありませんか」と急かさない。作って見せてから直すほうが早い。

## 構成パターン

```
ヒーロー（名前 ＋ 一言でどんな人か ＋ カテゴリのバッジ）
→ 一枚絵サマリー（この人を1枚で表す図）
→ できること3つ（カードグリッド。アイコン＋見出し＋2〜3文）
→ これまで（タイムライン。年 ＋ 出来事 ＋ そこで得たもの）
→ 大事にしていること／人柄（あれば）
→ 連絡先（ピル型のリンク。無ければ章ごと省く）
→ 作成日（小さく1行）
```

材料が少ないときは「これまで」と「大事にしていること」を省き、
**できること3つを厚く**する。章数より1章の密度を優先する。

## 書き方の指針

- **本人が言った言葉を残す。** 立派な言い回しに翻訳しない。「うまく言えないけど人の話を聞くのが好き」は、そのままのほうが伝わる
- **盛らない。** 実績を大きく見せる表現（「業界随一」「圧倒的」など）は本人が言っていない限り書かない
- **肩書きが無い人を軽く扱わない。** 会社名や役職が無くても、できることと人柄で1枚は成立する
- **「6. 誰に見せたいか」を構成に効かせる。** 仕事の相談を受けたいなら「できること」を前に厚く、採用向けなら「これまで」を前に厚くする
- デザインの水準・禁止事項は通常の図解と同じ（`model-answer.html` と SKILL.md の規定に従う）

## 公開前に必ず確認すること

自己紹介は本人の個人情報そのもの。**公開前に、この2点を確認する。**

> 公開すると、URLを知っている人は誰でも見られる状態になります（パスワードはかかりません）。
>
> 1. この内容で公開して大丈夫ですか
> 2. 連絡先（メールアドレス・電話番号）を載せたままでよいですか
>
> 電話番号や住所は、載せないことをおすすめします。

**電話番号・住所・生年月日が入っていたら、自分から「外しますか」と提案する。**
本人が載せたいと言えば従うが、確認なしに載せない。

## 公開できたあと

一周が終わったことを伝え、**ここからは何でも作れる**と案内する。

> 公開できました。これがあなたのページです。
>
> ここから先は、同じように話しかけるだけで何でも図解にできます。
>
> - 「インスタントコーヒーの美味しい入れ方を図解して」
> - 「この資料を、お客さんに見せる提案用に図解して」（ファイルを渡してもOK）
>
> 消したくなったら「この図解を削除して」と言ってください。

案内したら `.setup-done` を作成する。以降はこのファイルを参照しない。
