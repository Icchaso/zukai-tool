# 利用目的別ガイド

図解は「誰に見せるか」で作り方が変わる。このツールでは利用目的を3つに分けて扱う。

## 読者の前提

| 属性 | 内容 |
|------|------|
| 読者 | そのトピックにそれほど詳しくない人（本人・クライアント・チームメンバー） |
| 読み方 | 短時間で全体像をつかみたい。長文は読まれない前提 |
| 必要な配慮 | 専門用語は初出で括弧解説。図の順番を追うだけで理解できる構成 |

## 目的の見分け方

| 目的 | 依頼に含まれやすい言葉 |
|------|--------------------------------------|
| 自分用 | 「自分用」「理解したい」「勉強用」「整理したい」「メモ」「まとめたい」 |
| 提案用 | 「提案」「クライアント」「お客様」「営業」「商談」「見せる」「納品」 |
| 社内共有用 | 「社内」「チーム」「メンバー」「共有」「展開」「引き継ぎ」「オンボーディング」 |

判定できないときはこの3択で確認する:

> この図解の主な用途を教えてください:
> 1. **自分用** — 自分の理解・参照用
> 2. **提案用** — クライアント・取引先に見せる資料
> 3. **社内共有用** — チームへの共有・展開用

手がかりが何も無いときのデフォルトは**自分用**。添付素材から推測できるとき（顧客名入り→提案用、社内フロー→社内共有用）はその目的を採用し、冒頭で「◯◯用として作りますね」と伝える。

---

## 自分用 — 後から見返す「自分の辞書」

**価値**: 3ヶ月後に見返しても5秒で思い出せること。

| 要素 | 指針 |
|------|------|
| 冒頭 | 核心の定義1文から。回りくどい導入は不要 |
| 力点 | 網羅性。エッジケース・よくある誤解・落とし穴まで含める |
| 情報量 | 多め。「辞書」としての価値を優先 |
| トーン | 簡潔・直接的 |
| 出典 | 積極的に記載し、原典に戻れるようにする |
| 結び | クイックリファレンス（要点一覧）か「落とし穴リスト」 |

構成パターン:

```
ヒーロー（トピック＋一言定義）
→ 一枚絵サマリー
→ 各論（網羅的に）
→ よくある誤解・落とし穴
→ クイックリファレンス
→ 出典・情報ソース
```

## 提案用 — 相手が「これなら解決できそう」と思う資料

**価値**: 読者（意思決定者）が課題の理解者だと感じ、次の行動が明確になること。

| 要素 | 指針 |
|------|------|
| 冒頭 | 相手の課題・現状の言語化から入る（共感が先、解決策は後） |
| 力点 | 課題 → 解決策 → 効果 の一本線 |
| 情報量 | 判断に必要な分だけ。各セクションは「要するに何か」が一目でわかること |
| トーン | 専門性と信頼感。断定的だが押しつけない |
| 出典 | 信頼性を高めるものだけ厳選 |
| 結び | 「次のステップ」を具体的に示す |

構成パターン:

```
ヒーロー（テーマ＋相手の課題の言語化）
→ 現状の課題の図解（共感ポイント）
→ 解決策の全体像（一枚の図）
→ 具体的な仕組み
→ 期待される効果（数字・事例・ビフォーアフター）
→ 進め方・次のステップ
→ 出典・情報ソース
```

特に意識すること:

- **相手の言葉で書く** — 技術用語ではなく相手の業界の言葉。読者を主語に（「このツールは〜できる」ではなく「御社の〜が改善される」）
- **数字を添える** — 「効率化できます」ではなく「月あたり約◯時間の削減」。概算でも数字があると説得力が変わる
- **視覚の洗練を一段上げる** — 余白・整列・配色の統一感が、そのまま信頼感になる

## 社内共有用 — 全員が同じ理解で動ける資料

**価値**: 読んだ全員が「全体の流れ」と「自分の担当」を把握し、後から入った人もキャッチアップできること。

| 要素 | 指針 |
|------|------|
| 冒頭 | なぜこの共有をするのか（背景・目的）。「自分に関係ある」と思える入り |
| 力点 | 役割 → プロセス → アクション |
| 情報量 | 行動に必要な分だけ。「で、自分は何をすればいい？」に答える |
| トーン | フラットで実践的。チームの一員として語る |
| 出典 | 必要に応じて。社内資料へのリンクがあれば添える |
| 結び | アクションアイテム（担当・内容・期限） |

構成パターン:

```
ヒーロー（テーマ＋共有の目的）
→ プロセス全体の俯瞰図
→ 役割分担（色分け＋凡例）
→ 各ステップの詳細・判断基準
→ 注意点・よくあるミス
→ アクションアイテム
→ 出典・情報ソース
```

特に意識すること:

- **役割の色を図解全体で統一**し、凡例を添える
- **ハンドオフ（引き継ぎ）点を矢印＋ラベルで明示**する。責任の境界を曖昧にしない
- **判断が分かれる箇所には判断基準**（どういう条件ならどうする）を添える
- **更新前提の情報には「最終更新: YYYY年M月」**を添える
- **質問の受け皿**（不明点は誰に聞くか）を最後に書く

---

## 出典・情報ソース（全目的共通・必須）

どの目的でも、図解の末尾に「出典・情報ソース」セクションを置く。記載は各出典につき **ソース名／URL／発表日／取得日** のセット。ユーザー提供素材は「ユーザー提供資料: ◯◯／提供日: YYYY年M月D日」とする。最後に「この図解の作成日: YYYY年M月D日」を1行添える。
